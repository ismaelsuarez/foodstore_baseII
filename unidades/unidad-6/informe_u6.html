Salud y mantenimiento

  • health_check.sql terminó con código 0 en ambas bases (7942 kB, 1 sesión). Registra métricas, sin semáforo. En el origen, pedido tiene 5 filas muertas estimadas (50 %).
  • En el diagnóstico, la copia restaurada no tenía estadísticas y no alcanzaba el umbral de autoanalyze (50 + 0,1·n). Se ejecutó un ANALYZE puntual sobre detalle_pedido, con la justificación registrada; los conteos se conservaron. Sin VACUUM FULL.

Problema real y corrección

  • restore_test.sh se conectaba a la base de origen para comprobar el destino y para createdb, así que no podía restaurar si el origen ya no existía. Se agregó el parámetro obligatorio -a BASE_ADMINISTRATIVA y se probó con el nombre de origen ausente (docs/correccion_restauracion.md).
  • La guía de evaluación ocultaba el código de salida del script en P7 y P9. Se corrigió y luego se verificaron los bloques finales con una base de destino propia: respaldo correcto (0) y fallido (1), restauración (0) y destino existente (2). En todos los casos el bloque devolvió el mismo código que el script (docs/ensayo_evaluacion.md).

Mejora concreta

Exportar una instantánea (pg_export_snapshot()) y usarla tanto para la línea base como para pg_dump --snapshot. Así ambas reflejarían el mismo estado, sin depender de una ventana sin escrituras.
